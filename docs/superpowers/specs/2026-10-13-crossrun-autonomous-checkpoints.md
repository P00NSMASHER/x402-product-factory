# Cross-run autonomous build checkpoints — design

**Purpose:** Increase the reliability of automatic candidate generation so each isolated six-hour CI invocation can resume prior verified work instead of restarting the entire product fleet. The active GitHub PR chain is draft-only and commercial activation remains held.

**Approaches considered:** (1) Paid persistent cloud database/storage — rejected: requires spending, hosting and new credentials. (2) Commit mutable artifacts to Git default branch — rejected: violates protected write/release governance and expands repo size. (3) Restore recent same-branch GitHub Actions artifacts under a read-only token, then independently verify them before reuse — selected. Offer a static fleet QA dashboard to surface true output, missed work and quarantines.

**Data flow:** PR/scheduled CI checkout → prior successful same-branch artifact discovery via read-only GitHub Actions token → staging extraction → owner-private permissions → source-aware checkpoint importer → current pinned six-hour cycle → full-stack packaged app acceptance → up to three current researched idea builds → fleet ledger/report → seven-day artifact. A first run has no prior state; a wrong-branch, corrupt, forged, unverified fixture or source-stale artifact is never accepted. Older build records may be carried forward only while source identity and full verification receipts match.

**Boundaries:** At most 32 imported receipts and 12 MiB package data; max 64 fleet ledger slots; job timeout unchanged at nine minutes. No new money or outbound APIs other than authorized GitHub Actions reads, no PR merge, public deployment, sales, contact data, credentials in artifacts, release approvals, product registry changes, or account schedule changes. A temporary GitHub artifact is not an offsite backup. Independent commercial reality stays unknown.

**Verification:** adversarial checkpoint tests for tamper, wrong source, symlink, fixture-only evidence, partial restore and quarantine; CLI tests for private output/no overwrite and strict args; deterministic fleet summary and mobile static HTML; exact-head GitHub Actions CI with real cross-run restore, four prior candidates recovered, and source-scoped pinned current-cycle verification. User-facing status should distinguish green technical tests from running default-branch cron and real business results.
