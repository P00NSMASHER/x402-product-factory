# Verified recovery for generated applications

## Owner outcome and scope
Continue the owner's delegated autonomy upgrade without showing a new prompt or requiring another confirmation. Add automatically verified encrypted backups for the existing local runtime and evidence vault. Do not merge, deploy, send messages, spend, or alter account schedules. Restore is an explicit operator action to a NEW directory, never an automatic destructive rollback.

## Design
Use SQLite VACUUM INTO on separate read connections while a coordinating BEGIN IMMEDIATE transaction reserves BOTH source databases. Execute this bounded snapshot synchronously so the local service does not interleave a mutation. Include committed WAL contents; never copy the main file alone. Freeze only for snapshot creation; validate and encrypt afterward. Store runtime.sqlite and optional documents.sqlite in one authenticated AES-256-GCM bundle. A separate caller-supplied 32-byte backup key is mandatory; no keys or raw credentials are serialized. The existing vault key is additionally required to authenticate every encrypted document during verification.

Verify both database application IDs, exact v1 table columns, integrity/foreign keys, every existing kernel snapshot and every encrypted document including its tenant/workspace/record/requirement binding. Publish only after decrypting and verifying the written bundle. Bound each database at 32 MiB and the encrypted envelope at 96 MiB. This is a small single-host implementation, not large-database/high-availability infrastructure.

Use private, non-symlink directories outside the source repository. Backups must be outside the live state tree. Publish by exclusive hard link from a private staging area; fsync bundle and parent. Retain seven authenticated snapshots for this exact source; never delete an unrecognized, corrupt or other-source file. Stop with a sanitized error on unknown schema, missing keys, corruption or contention; leave source files and prior good backups untouched.

A supervisor takes one immediate validated snapshot (or verifies and resumes from the latest one after restart), then every six hours while the serve process runs. Use bounded retries after errors and no overlapping ticks. Opt in through FACTORY_BACKUP_KEY_HEX and FACTORY_BACKUP_DIR; without both, keep current behavior. No OS/cloud scheduler installation.

Restore verifies before publishing, creates a fresh directory, rotates ALL stored credential digests to random unrecoverable values, clears job leases and pauses all workspaces. Operators must reissue keys and explicitly resume; stale revoked credentials must not return after rollback. Original sources never change. Retention, backup and vault keys still need off-host operator protection.

## Verification
Test first: encrypted roundtrip, paired WAL state, corruption/keys/schema, orphan evidence, snapshots, source locks, quotas/paths, restore no-overwrite, old credentials and leases, retention safety, restart-aware schedule and sanitized retry behavior. Run focused tests locally; exact-head full repository and inherited browser CI are required. No independent reviewer/security certification is implied.
