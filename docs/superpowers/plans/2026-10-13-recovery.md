# Application recovery implementation plan

> Execute inline, with test-first implementation and explicit self-review. No independent reviewer is available in this session.

**Goal:** Automatically produce verified encrypted recovery points for existing generated apps.
**Architecture:** A synchronous paired SQLite snapshot and authenticated recovery bundle, with a bounded service supervisor. Recovery publishes only a new private state directory and invalidates old access credentials.
**Tech stack:** Node.js 22.16+, node:sqlite, node:crypto, node:fs; no new dependencies.
**Spec:** ../specs/2026-10-13-recovery.md

## Tasks
- [ ] Write and run failing `runtime/recovery.test.js` contract tests.
- [ ] Implement `runtime/recovery.js`: safe paths, paired snapshots, envelope validation, semantic restore verification and non-destructive restore.
- [ ] Implement `runtime/recovery-supervisor.js`, with restart-aware cadence, bounded retry and scoped retention.
- [ ] Add `scripts/application-recovery.js` operator capture/verify/restore/reissue commands and opt-in wiring in the existing runtime CLI.
- [ ] Add integration coverage using the real runtime/vault and child processes; verify exact-head full CI and inherited browser journeys.
- [ ] Record observed acceptance and remaining limits in documentation and the PR receipt.

## Review focus
Wrong keys/corrupt newest backup must never report green; never overwrite live state; never resurrect revoked credentials or expired worker leases; never drop a vault silently; never prune unrelated or unauthenticated files. Synchronous work is bounded, but may briefly delay local API responses. No automatic replacement of the live database is authorized.
